# Component requirements

## Buttons
- Distinct primary, secondary, destructive and disabled appearances; accessible names; loading state must not enable duplicate submissions.

## Forms
- Visible labels, meaningful helper text, clear validation near fields, keyboard focus; never substitute placeholder for label.

## Navigation
- Current location evident, back behavior predictable; menu keyboard support and meaningful landmarks for web.

## Cards and lists
- Hierarchy via spacing and typography. Only make whole cards clickable if interaction and semantics are sound; never nest interactive elements improperly.

## Search and filters
- Show applied filters, reset action, and results/empty states. Debounce if appropriate, retain keyboard usability.

## Dialogs and sheets
- Clear title, focus management, Escape and dismissal behavior appropriate to semantics, destructive action confirmation when warranted.

## Status and system feedback
- Loading, progress, success and failure should be distinguishable without relying solely on color or animation.

## Icons and imagery
- Icons support labels rather than replace clear text in critical actions; decorative icons hidden from assistive tech.
- Do not copy or redistribute Apple graphics, UI kits, logos or fonts without checking the asset's own terms.
